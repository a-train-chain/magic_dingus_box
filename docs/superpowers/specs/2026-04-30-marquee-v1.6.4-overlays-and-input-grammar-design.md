# Overview

Four cohesive UX additions to the Marquee Media Browser, sequenced as a single v1.6.4 release:

1. **Discover-style filter overlay** for Popular + Top Rated tabs (BTN4)
2. **Search keyboard ↔ results-grid focus toggle** (BTN4)
3. **BTN2 = exit-to-kiosk** with yes/no confirm modal (replaces v1.6.3's BTN2=back wiring)
4. **Rotary-press playback overlay** with detail header + similar-films strip

Common DNA: reuse the slide-in overlay primitive established in v1.6.3 LibraryScreen, reuse footer hint icons, surface overlay state through `AppState::DisplaySettings`.

# Feature 1: Discover filter overlay

## Trigger
BTN4 toggles a left-side slide-in overlay on Popular and Top Rated tabs. Same animation curves and visual structure as the Library overlay (200ms slide-in, 150ms slide-out, cubic ease).

## Endpoint strategy (hybrid)
- All filters at default ("Any") → call existing `/movie/popular` or `/movie/top_rated` endpoints (no behavioral drift from current state).
- Any filter non-default → switch to `/discover/movie` with the right `sort_by` baseline plus the layered filter params.

This preserves the current "first-time launch" experience and only invokes Discover when the user actively customizes.

Discover baselines:
- Popular: `sort_by=popularity.desc&vote_count.gte=200`
- Top Rated: `sort_by=vote_average.desc&vote_count.gte=300`

## Filter parameters

| Filter | Type | Values | TMDB Discover param |
|---|---|---|---|
| Genre | multi-select | TMDB top-level genres (Action, Comedy, Drama, Horror, Sci-Fi, Thriller, Romance, Animation, Documentary, Fantasy, Adventure, Crime, Mystery, Family, War, Western, Music, History) | `with_genres` (comma-joined) |
| Decade | single | Any / 2020s / 2010s / 2000s / 1990s / 1980s / 1970s / Classic (pre-1970) | `primary_release_date.gte` + `primary_release_date.lte` |
| Min rating | single | Any / 6.0+ / 7.0+ / 8.0+ | `vote_average.gte` |
| Runtime | single | Any / Under 90min / 90-120min / 2-3hr / Over 3hr | `with_runtime.gte` + `with_runtime.lte` |
| Original language | single | Any / English / Japanese / French / Spanish / Korean / Italian / German / Hindi / Mandarin | `with_original_language` (ISO 639-1) |
| Sort by | single | Popularity / Top Rated / Most Voted / Recent Release | `sort_by` |

Plus a "Reset all" action row at the bottom of the overlay.

## Persistence
Per-tab persistence in `config/settings.json`. Two parallel sets in `DisplaySettings`:

```cpp
// Popular tab
uint32_t mb_popular_genre_mask;        // bitmask of selected genres
MbDecade mb_popular_decade;
MbMinRating mb_popular_min_rating;
MbRuntime mb_popular_runtime;
MbLanguage mb_popular_language;
MbDiscoverSort mb_popular_sort;

// Top Rated tab — same shape, mb_toprated_* prefix
```

Defaults: all "Any", which means the hybrid endpoint strategy keeps existing behavior.

## Render
Reuse the LibraryScreen overlay panel structure: bg_lift fill, gold left + top + bottom rules, dim section labels, gold cursor row marker pointing right toward the focused row's value list. Replace Library's 8 focus rows with:

1. GENRE — chip group (multiple lines if needed; cursor moves through chips)
2. DECADE — single value selector
3. MIN RATING — single value selector
4. RUNTIME — single value selector
5. LANGUAGE — single value selector
6. SORT BY — single value selector
7. RESET ALL — action row

Selecting a value commits immediately and triggers the underlying tab's grid to refetch (Discover or default endpoint per hybrid strategy).

## Edge cases
- TMDB Discover failure → toast "Discovery unavailable"; previous grid stays until next selection.
- Discover returns empty page (over-filtered) → grid shows "No films match these filters" placeholder with hint to reset.

# Feature 2: Search keyboard ↔ grid focus toggle

## Trigger
BTN4 toggles focus between the on-screen keyboard and the search results grid below. BTN4 is dimmed (no-op label "—") when the results list is empty.

## Visual indicators
- Keyboard focused (default state): selected key has the gold cursor; results grid renders at 70% alpha (visibly "out of focus")
- Grid focused: gold cursor on highlighted poster; keyboard renders at 50% alpha

Transition fades over ~150ms.

## Input grammar (grid focus)
- Rotary rotate = navigate posters (1D wraparound across 9-column grid; row order = scroll order)
- Rotary press = open Detail for highlighted movie (origin_=Search)
- BTN1/BTN3 = tab PREV/NEXT (unchanged)
- BTN2 = exit-to-kiosk modal (new universal binding)
- BTN4 = back to keyboard focus
- Physical keyboard typing: snaps focus back to keyboard automatically (any keypress triggers focus restore)

## State persistence
Focus state is in-memory only — fresh visit to Search starts with keyboard focus. State preserved across BTN4 toggles within a single Search visit.

# Feature 3: BTN2 = exit-to-kiosk with confirm modal

## Inversion of v1.6.3
v1.6.3 wired BTN2 to "back" across MB. v1.6.4 changes BTN2 to a global "Exit Marquee" trigger. Justification: tab nav (BTN1/BTN3) handles all within-MB navigation, so a contextual back button is redundant. Exit is the high-value binding.

## Universal application
Every MB screen — Popular, Top Rated, Search, Library, Queue, Settings, Detail, Playback — listens for BTN2 to open the exit modal.

## Modal layout
- Center card, ~440×180px on a dimmed (~40% alpha black) background that covers the rest of the screen
- Headline: "Exit Marquee?" (gold, font 28px)
- Subtitle: "Return to the main menu" (dim, font 16px)
- Two pill buttons in a row: `Cancel` (left, default focus) | `Exit` (right)
  - Focused button: gold fill, bg text
  - Unfocused button: bg_lift fill + 1px gold border, fg text
- Card itself: bg_lift fill + 1px gold border, ~12px corner radius equivalent (chrome's draw_rounded_rect)

## Default focus
`Cancel`. Rationale: accidental BTN2 press should not drop the user out of MB. Quick-confirm via BTN2-tap-twice is available for users who know what they want.

## Input grammar (modal open)
- Rotary rotate / BTN1 / BTN3 = toggle focus between Cancel and Exit
- Rotary press = commit highlighted button
- BTN2 (again) = quick-confirm Exit (regardless of focus)
- BTN4 = same as Cancel (close modal, no exit)

## Exit action
Yes path:
1. If MB is in Playback, stop GStreamer pipeline + free the texture cache
2. Set `state.media_browser_active = false` (returns control to kiosk main UI)
3. Modal closes implicitly with the screen transition

## Detail screen "back" rewire
Previously: BTN2 = back to originating list. New: BTN4 = back to originating list. BTN4 was a no-op on Detail in v1.6.3, so this fits cleanly without further input grammar conflicts.

## Coexistence with sub-overlays
When any sub-overlay (filter overlay, library overlay, playback overlay) is open, BTN2 still opens the exit modal. The sub-overlay stays underneath the dimmed exit-modal background. If user cancels, the sub-overlay remains. Predictable mental model: "BTN2 always means I want to leave."

# Feature 4: Rotary-press playback overlay

## Trigger
- Rotary press during MB playback (no overlay open) = open overlay
- Rotary press while overlay is open + cursor on a similar-film poster = quick-add highlighted film
- BTN4 = close overlay

Note: rotary press serves two roles depending on overlay state. This matches the universal MB convention "rotary press = SELECT in current context."

## Layout
Bottom ~1/3 of screen (~360px tall on 1080p). Translucent panel: `bg_lift` at 85% alpha + 1px gold rule along the top edge. Movie remains visible across the top 2/3 of the screen with no opacity wash.

## Detail header (top of panel, ~80px)
- Left: small poster thumbnail (~60px wide, 90px tall, hardlinked to the cached poster from PlaybackScreen state)
- Right of thumbnail:
  - Line 1: title (fg, font 22px) + " · " + year + " · " + runtime + " · " + genres (dim, font 16px)
  - Lines 2-3: synopsis truncated to 2 lines (dim, font 14px)
- 1px dim rule beneath header separating it from the similar strip

## Similar-films strip (~270px tall)
- TMDB `/movie/{id}/similar` results
- Up to 10 films total, 5 visible at once
- Each poster card: ~120px wide × 180px tall, with title under poster
- Cursor: 2px gold outline on focused poster + slight scale-up (1.02)
- Rotary rotate moves cursor through 10 films; off-screen films scroll into view
- "STILL TO COME" or similar header? No — keep the strip clean and self-explanatory.

## Pre-fetch
On MB playback start (i.e., transition from Detail to Playback), kick off a background thread to fetch `/movie/{id}/similar`. Cache the result in PlaybackScreen state. Opening the overlay reads from cache → instant render. If fetch is still in-flight when overlay opens, similar strip shows a loading shimmer briefly.

## Quick-add action
Rotary press on highlighted similar-film poster:
1. Issue Radarr `AddMovie` (monitored=true, searchOnAdd=true, qualityProfileId="Any")
2. Show inline toast next to the poster: "Added — searching for release" (gold text on bg_lift card, ~2s)
3. Toast dismisses; cursor remains on the same poster; movie continues playing
4. If Radarr returns "MovieAlreadyExists" → toast "Already in library"
5. If Radarr request fails → toast "Couldn't add — try again later"

## Edge cases
- Local file with no TMDB ID → overlay opens; detail header shows file metadata (filename + duration); similar strip shows "No related films" placeholder.
- TMDB similar fetch fails → similar strip shows "Couldn't load related films" + retry hint (rotary press to retry).
- TMDB returns empty similar list → "No related films found" placeholder.

## Footer hints (overlay open during playback)
- Rotary = "Browse Similar / Quick Add"
- BTN4 = "Close"
- BTN2 = "Exit"
- BTN1/BTN3 = dimmed (no-op)

# Out of scope

- TMDB Discover infinite scroll / pagination (use TMDB's default first-page result for now)
- Localization of TMDB genre names / language names (use TMDB-provided English strings)
- Adding ratings/reviews to similar-films posters in playback overlay (keeps overlay light)
- Persistent watchlist concept (quick-add to Radarr is the chosen action)
- Filter overlay for Search tab (Search has its own query mechanism; no Discover layer needed)
- Filter overlay for Queue tab (Queue is a live list, not a discovery surface)
