# Perf: the Tube output programs at 4 QPU threads — report

Status: **DONE_WITH_CONCERNS**. The tool is built and committed. A rewrite of `output.frag` that is
picture-neutral and puts **all ten output programs in 4-thread mode** exists (variant "vP1"). It is
**NOT committed**, for two reasons:
1. It fails the acceptance rule on instruction growth: the raster programs grow by 10-11 %.
2. On the Pi it is **slower**, not faster. The premise behind this task, that 2-thread mode roughly
   doubles the shader's time, did not hold in an interleaved A/B. The output pass's time tracks the
   instruction count (SFU-heavy instructions most of all), not the thread count. Details are in "The
   finding" below.

The preview kiosk the controller asked for is built **with vP1 applied** (uncommitted), so the frame
rate can be measured in the kiosk (GPU timers) against the existing 695a48b binary, whose shader
source is identical to HEAD's. See "Builds" below.

the minimum repeats to ±0.03 ms across rounds. The kiosk shares the GPU, so read these relative to

In two pairs the thread count changes and almost nothing else does (474/2t against 523/4t; 417/2t
against 445/4t). In both pairs the 4-thread program is slower, by roughly its extra instructions. So
on this GPU, with this shader, 2 threads are not a 2x penalty. The output pass is bound by its
instructions: ALU work plus SFU ops (rcp, exp, sqrt, sin, log). The kiosk measured 15.6 ms on the
raster output against 11.3 ms on the signal output. That gap is explained by the raster program's
two extra beam-weighted line taps (about 36 SFU ops per pixel) and its extra instructions, not by
the thread count. Caveat: this is the off-screen tool, not the kiosk's GPU timers. Running the
preview binary below in the kiosk is the definitive test.

## Step 1 — the tool (commit 81f85ef)

`magic_dingus_box_cpp/scripts/dev/tube_shaderstat/shaderstat.cpp` + `README.md`.
- **Context.** GBM + EGL on `/dev/dri/renderD128`, falling back to EGL's surfaceless platform, with
  an ES 3.1 context and no surface. It never opens a card node and never touches KMS. Mesa's disk
  cache is disabled for the process, because a cache hit skips the compile and its shaderdb line,
  and the cache would write under `~/.cache`.
- **Fidelity.** Every sampler is bound to a texture of the renderer's internal format on the
  renderer's unit (`kSamplerUnits`):
  - `ui`: SRGB8_ALPHA8 with DECODE when the source has `SCENE_HW_DECODE`, else RGBA8;
  - `glowTex`, `prev`, `quarter`: SRGB8_ALPHA8;
  - `signalTex`, `linesTex`: RGBA16F;
  - `glassTex`, `maskTex`: RGBA8, the mask NEAREST + REPEAT.

  The target is the program's own. An OUT_HISTORY program draws into a picture-sized SRGB8_ALPHA8
  target with FRAMEBUFFER_SRGB on and uOrigin 0,0. Any other program draws into a 1920x1080 RGBA8
  target, cleared first, through the 240,0 1440x1080 viewport. uSceneMap and uSceneClamp are
  computed as `scene_uniforms()` computes them.
- **Modes.**
  - Statistics: the fragment shaderdb line, captured from stderr and printed compactly.
  - `--time N`: each frame bracketed by glFinish; prints median, mean and minimum.
  - `--compare A B` with any number of `--uniforms` files: one compile per program, then every
    file drawn through both, read back, and the largest per-channel difference reported with the
    count of pixels that differ by more than 1/255 (exit 3 if any do).
  - `--float`: an RGBA32F target for a finer comparison.
- **Errors.** Exit 1 on a compile or link error (the log is printed), a GL or EGL failure, or an
  incomplete framebuffer. Exit 2 on usage errors, an unreadable source or uniform file, or a bad
  line in a uniform file. It compiles with no warnings under `-Wall -Wextra` in the arm64 container
  and on the Pi.
- **Uniform writer.** `MDB_WRITE_TUBE_UNIFORMS=<dir>` on `test_app_unit "[tube_shaders]"` (in
  `tests/app/test_tube_shaders.cpp`) writes three files per look, 18 in all. It drives FrameDriver
  from t=100 s at 30 fps to 106.4 s and feeds a mean of 0.35.
  - `<look>.txt`: the mid-run frame. Warm-up is over and the phases are non-zero.
  - `<look>.degauss.txt`: a degauss started at 106.0, degauss = 0.74.
  - `<look>.synthetic.txt`: NOT a driver frame. Power 0.6, spot 0.3, warmupGain 0.7, with roll
    band, purity, tracking and flagging turned on, because no look moves them.

  Each file holds every TubeUniforms field (with a static_assert that none is missing), tint,
  uMaskSize, uSceneMap and uSceneClamp, plus `@fb`, `@pic` and `@mask` (the look's real tile, for
  example the 3x12 slot mask).
- **Checked against the kiosk.** All ten output programs reproduce the measurement file's section 3
  exactly (table below). Two sanity checks of the comparison:
  - A program against itself: 0 differences.
  - out_rich_signal against out_rich_raster: 0 differences with Monitor's uniforms (raster 0, so the
    mix is an identity, which is correct), and up to 111/255 in 1.5 M pixels with TV's.

## Step 3 — 4 threads, picture unchanged (variant vP1: reached, not adopted)

vP1 is four changes to `output.frag`. Each is result-neutral, and all four are needed (see the
experiments below). Patch:
`.superpowers/sdd/2026-11-15-tube-crt-renderer/perf-4thread-vP1.patch` (69 lines, against HEAD).
1. **Glass fetched after the lit block.** The block's condition becomes `lit`; then the glass is
   fetched, then `col *= glass.a; col += glass.rgb / 32.0`.
   - Neutral: where lit but glass.a == 0 the old shader gave col = 0, and the new one gives
     finite × 0 = 0.
   - Cost: the lit-but-transparent corner pixels now run the block.
2. **The power-off spot from `p`.** `q = (2.0 * p - outSize) / outH` in place of
   `n * vec2(outW / outH, 1.0)`. The two are algebraically identical, and `n` then dies after
   `ndOf`.
3. **Raster and native taps accumulated one line at a time.**
   - Before: `mix(mix(native, rastered, raster)` with `rastered = mix(mix(c0,c1,s), c0*w0 + c1*w1,
     scanlines)`.
   - After: `beamed = native*(1-raster) + c0*raster*mix(1-s, w0, scanlines) + c1*raster*mix(s, w1,
     scanlines)`.
   - The same linear combination, distributed. RASTER_ONLY keeps a share of 1.0 and no native tap.
4. **The late power multiply no longer shares its subexpression with `ndOf`.**
   `smoothstep(0.18, 1.0, min(power, 1.0))` replaces `smoothstep(0.18, 1.0, power)`. This is
   exactly equal for every input, because smoothstep clamps above 1. It breaks the CSE that kept
   `max(smoothstep(0.18,1,power),0.003)` (vOpen) live from the start of the shader to the end. This
   was the deciding register.

Uniforms read are unchanged, so `uniforms_of` needs no edit, and the cap substrings are untouched.
With vP1 applied, `[tube_shaders]` passes and the validator reports 29 checked, 0 failed. Then
`output.frag` was restored.

## Step 4 — cheaper elsewhere

Instruction count is what costs, so these are ranked by expected saving.

1. **Precompute the uniform-only work on the CPU** (vU; statistics plus a fair timing with real
   derived values). `output.frag` computes about 30 values per pixel that depend only on uniforms,
   among them about 15 reciprocals (SFU):
   - 2/outSize; 1/outW and 1/outH;
   - the bend divisor 1/mix(flatFit, inset, curvature);
   - 1/(hOpen, vOpen) and the breathe divisor;
   - lines/outH and 1/ceil(lines); beamMax-beamMin;
   - rollOff's gain, start, room and 1/room; 1/uMaskSize;
   - the ABL factor; the noise grain reciprocal, nz·0.1 and nz·0.012;
   - the flicker factor; the hum scale, phase and amplitude;
   - the roll tint vec3; purity's centre, 1/pxPerMm and tint vec3;
   - the power gain; outW/outH; the history decay.

   As a hand variant with made-up uniforms, fed exact values by a script, it is picture-neutral:
   max 1/255 and 0 pixels over, on all 18 files, for raster_ag and signal.

   | program | inst | min ms |
   |---|---|---|
   | raster | 479 to 415 | |
   | raster_ag | 474 to 404 | 15.77 to **14.05 (-10.9 %)** |
   | raster_only | 476 to 392 | |
   | raster_only_ag | 441 to 392 | |
   | signal_ag | 412 to 340 | 12.56 to **10.98 (-12.6 %)** |

   It needs new uniforms: renderer-owned or TubeUniforms fields computed in `tube_frame`, plus
   `uniforms_of` and the upload tables. That is outside "the same uniforms", so it is not
   implemented. On the kiosk's 15.5 ms output pass it would save about 1.7 ms; about 1.4 ms on
   PVM/Monitor's 11-12 ms.
2. **Cheap beam** (option a): -9 % on raster_ag. It changes the picture.
3. **The beam's two divides per channel as one reciprocal** (vD): it RAISED instructions at
   2 threads (483 to 500) and was flat on signal_ag (411, 12.39 against 12.56 ms). Not worth it.
4. **`pow` with constant exponents:** only `pow(..., 2.32)` (hum) and the gamma curves remain, and
   none has an integer exponent. Nothing to replace.
5. **Duplicated texture reads:** none. Each tap is distinct, and texelFetch(glass) and
   texelFetch(prev) use the same coordinates but different textures.

Ideas that need a structural change (not implemented):
- **Afterglow copy as a framebuffer blit:** probably equivalent. The history stores linear light
  as sRGB-encoded bytes. copy_encode decodes those bytes on read and re-encodes them with the exact
  piecewise sRGB curve, so it writes back the same bytes. A raw `glBlitFramebuffer` (no
  conversion, FRAMEBUFFER_SRGB off) into the picture rectangle should therefore give the same
  picture without a shader pass. It saves part of the 2.5 ms history pass. Two things need checking
  on the hardware: the blit's own cost on V3D, and that the driver does not convert on an sRGB to
  UNORM blit.
- **A smaller blur target or fewer taps for large glow sigma:** glow costs 2.3-4.1 ms on
  arcade/tv. It changes the halation slightly.
- **The raster's half-width lines target read at full detail:** it is already half width; no
  change suggested.
- **Splitting the power block** (option b): a table change with driver switching, as above.

## Design

`tube::TubeDerived` is a plain struct of 36 floats, each one GLSL float uniform of the same name.
- **Computed by** `tube::tube_derived(const TubeUniforms&, DerivedSizes{mask_w, mask_h, signal_w,
  signal_h})`. It is pure and Mac-tested.
- **`kDerivedFields`** (name, member) carries a `static_assert(sizeof(TubeDerived) ==
  kDerivedFields.size() * sizeof(float))`, so a field cannot be added without being uploaded.
- **Renderer:**
  - `build()` resolves every listed d* name once into `ProgramSlot::derived_uploads`.
  - `draw_frame()` computes one `TubeDerived` on the stack after the targets and the mask are in
    place.
  - `upload_tube_uniforms(slot, u, derived)` sends them, with no allocation and no string lookup.
- **Own uniforms removed:** `uSigSize` and `uMaskSize`, since nothing reads them now.

| dInvHalfW, dInvHalfH | `p / (outSize * 0.5)` (n); signal `sp / (srcSize() * 0.5)` | every output; sig_guns* |

# Wide glow on a smaller target

Commits:
- `00642b3` shaderstat `--glowchain`.
- `5b11aa0` the change.
- `b5f67d2` shaderstat `--blit` (part C).

**The rule (`tube_programs.h`).** When a plan has a glow and `glow_sigma_px >= kGlowHalfSigma = 1.9`
(quarter px; GLOW SIZE 10 and up, which covers every shipped look), `PassPlan::glow_half` is set.

**What changes when it is set:**
- `TargetSizes::glow_w/h` become `(quarter + 1) / 2` (180×135 at 1440×1080); `target_bytes` uses them.
- `predicted_ms` prices the blur at `kPassCosts.glow_blur_half` = 0.75 ms. That figure is
  TOOL-measured (marked as such in `tube_budget.h`), not kiosk-measured.
- `blur_params(plan, glow_sigma)` gives the blur sigma `max(glow_sigma, 0.1) * 0.5`, the radius
  `min(ceil(3 sigma), 24)`, and `down`.

**Renderer.**
- `ensure_targets` makes `glow_tmp` and `glow_out` at `glow_w/h`.
- The H pass sets `uDown = 1` and reads the quarter. The quarter is LINEAR, as every target is made.
- The V pass sets `uDown = 0`.
- The output samples `glowTex` exactly as before.

**`blur.frag`.** It gains one `int uDown` (listed in `uniforms_of`) and a second loop behind the
uniform branch.
- The tap: each eighth-resolution tap `b` is ONE bilinear sample at uv `(2b + 1) / quarterSize`. That
  point is the shared corner of quarter texels 2b and 2b+1 in x and y, so the four texels weigh 1/4
  each: a 2×2 box prefilter.
- The edges: the block index is clamped to `[0, (size + 1) / 2 - 1]`. CLAMP_TO_EDGE averages an odd
  last column or row with itself.

What stays the same: the program table, the define sets, the radius cap 24, the sigma floor, and the
quarter target (chroma and the probe read it).

# Afterglow hand-off (measured only)

`shaderstat --blit` is a proxy: an RGBA8 framebuffer object stands in for the screen, because the
tool has no default framebuffer.
- **Bytes:** a 1440×1080 `glBlitFramebuffer` RGBA8 → SRGB8_ALPHA8, `GL_FRAMEBUFFER_SRGB_EXT`
  disabled, NEAREST, changed **0 of 6,220,800 bytes**, three runs out of three. The driver neither
  decodes nor encodes on this blit.
- **Time** (min / median of 100): 1.17 / 1.70, 1.22 / 1.77 and 1.19 / 1.85 ms.
- **For scale:** today's `copy_encode` (history → screen) measured 1.95–2.05 ms min with the same
  tool; the kiosk prices it at 2.4–2.5 ms.

**Verdict: not worth making.** The candidate replaces copy_encode (about 2.0 ms in the tool) with a
blit (about 1.2 ms). It also moves the output's write from the history to the screen, which the
kiosk measured at about +0.8 ms. Net: about 0 to 0.3 ms per afterglow frame.

Against that, it would need:
- the `_ag` outputs to encode;
- the history to hold encoded bytes, read back through the hardware decode;
- a blit from the real default framebuffer, which this proxy did not measure (the XRGB8888 screen,
  possibly a resolve);
- a new hardware validation.

The wide glow above saves ten times more for less risk.
